# Уведомления, реклама, сроки и обсуждения

## Как пользоваться

- В карточке мероприятия нажмите «Добавить шаблон», выберите фактические дни съёмки и ответственных. По умолчанию выбраны все дни. В раскрывающемся блоке «Разные ответственные по дням» можно отдельно назначить отправку фото и видео. Существующие исполнители, статусы и ручные сроки сохраняются; можно назначить задачи без исполнителя. У новой съёмки задачи появляются после применения шаблона.
- В Настройках → Шаблон задач → Изменить задайте тип «Отправка видео · 3 дня» или «Отправка фото · 22 дня». Название задачи свободное. На каждый тип отправки разрешена одна строка шаблона. Старые стандартные названия распознаются при первой миграции; нестандартным названиям назначьте тип вручную.
- Срок — календарная дата, до 23:59 включительно в часовом поясе мероприятия. Часовой пояс берётся из Google, при отсутствии используется Asia/Krasnoyarsk. Для съёмки 5–7 ноября видео требуется 8–10 ноября, фото — 27–29 ноября. Последний день Google для событий на весь день исключается. Перенос мероприятия в Google не сдвигает уже созданные задачи: проверьте фактические дни и при необходимости исправьте сроки вручную.
- В «Рекламе» администратор загружает несколько JPEG/PNG с общей подписью, до 10 МБ на исходный файл и до 25 мегапикселей. Изображения декодируются и пересохраняются без исходных метаданных. Участники могут открывать и скачивать их. Удаление доступно администратору.
- В «Обсуждении» все участники оставляют сообщения до 4000 символов. Автор редактирует и удаляет свои сообщения; администратор может удалять любые. Предыдущие сообщения загружаются кнопкой. Автоматический опрос каждые 5 секунд сохраняет черновик и позицию чтения.
- Колокольчик показывает историю выполнения задач и число непрочитанных. Уведомление содержит исполнителя, задачу и мероприятие; открывает карточку. «Прочитать все» относится только к текущему участнику.

## Обновление на Railway

1. Перед обновлением создайте резервную копию постоянного тома штатным способом Railway. Объединяйте PR только после проверки. В этом PR рабочие переменные, том и сервис не меняются.
2. Сохраните существующий том с Mount Path `/app/data`. База остаётся `/app/data/shootboard.sqlite`, баннеры сохраняются в `/app/data/uploads`. Не создавайте пустой том взамен существующего. Бэкап должен включать и базу, и uploads.
3. Установка зависимостей теперь обязательна: `npm ci`. Start Command можно оставить `npm start` либо `node server.mjs`. Railway должен использовать Node.js 22.13+; рекомендуется поддерживаемая версия 24. Используется один процесс/реплика с SQLite.
4. Существующие `ADMIN_PASSWORD_HASH`, `DATA_KEY`, Google OAuth и `APP_ORIGIN` оставьте прежними. Миграции выполняются при старте: добавляются таблицы/колонки/индексы; прежние задачи, сотрудники, сессии, аудит и токены Google не удаляются. Обычное чтение/чат работают без настройки Web Push.

## Включение Web Push

Библиотека: [web-push, официальная документация](https://github.com/web-push-libs/web-push).

Один раз на доверенном компьютере после `npm ci` выполните:

```sh
npx web-push generate-vapid-keys --json
```

Команда выдаст publicKey и privateKey. Сохраните их в менеджере паролей; не публикуйте вывод и не добавляйте его в репозиторий.

В Railway → сервис ShootBoard → Variables добавьте:

```text
VAPID_PUBLIC_KEY=<publicKey из команды>
VAPID_PRIVATE_KEY=<privateKey из команды>
VAPID_SUBJECT=https://shootboard-production.up.railway.app
```

Примените изменения с перезапуском. Каждый участник на каждом устройстве открывает колокольчик → «Включить уведомления» и разрешает их браузеру. Нужен HTTPS. Если разрешение запрещено, его меняют в настройках сайта в браузере. На iPhone/iPad Web Push может требовать установленное на домашний экран веб-приложение; поддержка и доставка зависят от браузера/ОС. Отдельный манифест установки в этом обновлении не добавлен. Встроенный центр уведомлений работает независимо от этого.

VAPID_PRIVATE_KEY остаётся только на сервере; публичный ключ выдаётся браузеру по авторизованному запросу. Не перевыпускайте пару при каждом деплое: после смены ключей устройства нужно подключить заново. `/sw.js` обслуживается с корня сайта и не кэширует страницы, API или приватные файлы.

Получатели — администратор и сотрудники с активными ссылками. Повторная отметка без изменения статуса не создаёт новое уведомление; возврат в работу не уведомляет; повторное выполнение после возврата создаёт новое. Уведомление, квитанции, очередь доставки, статус и аудит сохраняются одной транзакцией. Очередь переживает перезапуск, повторяет временные ошибки до 5 попыток; недействительные подписки удаляются. При отзыве/ротации ссылки подписки удаляются. Уже переданное внешней службе уведомление отозвать невозможно. Для повтора доставки используется одинаковый tag, чтобы браузер не создавал несколько карточек одного события. Строгое exactly-once между SQLite и сторонней push-службой не гарантируется.

Поддерживаемые push-службы: Google FCM, Mozilla, Apple и Windows. Сервер ограничивает адреса подписок этими службами, чтобы запросы не могли обращаться к произвольным внутренним адресам.

## Проверка

`npm test` проверяет права, аудит, миграции прежней схемы, дедлайны и выбор дней, сохранение ручных сроков/исполнителей, уведомления без дублей, отзыв подписок, сообщения, пагинацию, загрузку/проверку/скачивание баннеров и сохранность после перезапуска. Доставка push в тестах заменена контролируемым отправителем. После настройки VAPID нужна проверка с двумя настоящими устройствами, включая закрытую вкладку: внешняя доставка в среде разработки не проверялась.

В локальном браузере проверены отправка заметки, сохранение черновика при изменении статуса задачи, колокольчик, чтение уведомлений, переход в карточку, баннер и шаблон многодневной съёмки. Отдельная проверка всех мобильных браузеров не выполнялась.
