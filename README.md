# ShootBoard Mini

## Новое: шаблон с ответственными и графитная тема

В карточке съёмки → «Подготовка» → «Добавить шаблон» выберите задачи и ответственных. Можно назначить одного сотрудника на весь список. Галочка «Запомнить ответственных» сохранит выбор для следующих съёмок. Существующие задачи не дублируются, их выполнение и сроки сохраняются; ответственные обновляются согласно выбору. Состав списка меняется в Настройках → Шаблон задач → Изменить. Применение доступно только администратору, включая съёмки, импортированные из Google.

Все экраны используют графитную тёмную тему с пастельными синими и оранжевыми акцентами. Пересекающиеся по времени мероприятия получают разные цвета, одинаковые во всех недельных частях полосы, списке и карточке. При нескольких пересечениях используются дополнительные оттенки синего и оранжевого. После изменения расписания цвета могут перераспределиться.

Обновление: остановите приложение через Ctrl+C, сохраните копию рабочей папки, замените только server.mjs и всю папку public/. Свои .env и data/ оставьте на месте. Запустите start.cmd и нажмите Ctrl+F5 в браузере. Google переподключать не нужно. Проверены 14 автоматических тестов и применение шаблона с разными ответственными в браузере.

Готовая самостоятельная реализация для небольшой команды: сервер Node.js, постоянная SQLite, русский интерфейс без сборки и внешних зависимостей. Node.js 22.13+ (проверено на 22.14). Вместо Next.js выбран минимальный стек, чтобы приложение можно было запустить без установки пакетов.

## Запуск

Откройте терминал в этой папке:

```powershell
npm run setup
npm start
```

При настройке задайте единственный пароль администратора длиной от 14 символов. Он не включён в поставку. Откройте http://localhost:4318. В пустом расписании можно добавить тестовые съёмки; это отдельная явная кнопка, реальные данные автоматически не подставляются.

`npm test` запускает проверки доступа и сохранения данных.

## Доступ команды

1. Войдите как администратор → Настройки → Сотрудник.
2. Введите только имя. Скопируйте показанную персональную ссылку и передайте человеку лично.
3. Назначьте человека на съёмку с нужной ролью и выберите его ответственным в задачах.
4. Сотрудник открывает ссылку без регистрации, видит общее расписание, свои назначения, роль, задачи и общий прогресс. Меняет только свои задачи.
5. «Отозвать» закрывает все его сессии; «Новая ссылка» одновременно отзывает прежнюю ссылку и сессии. Посмотреть прежний токен нельзя: в базе только SHA-256-хеш.

Повторное открытие действующей ссылки разрешено для другого устройства. Ссылка действует до отзыва. Сессия сотрудника — 14 дней, администратора — 12 часов; срок абсолютный. Это сознательно простой доступ по владению ссылкой, поэтому её нельзя публиковать в общедоступном чате.

## Защита

- Токены доступа и сессий: 32 криптографически случайных байта (256 бит). В SQLite хранятся только хеши.
- Токен ссылки находится после `#`, поэтому не попадает в HTTP-URL, прокси-логи и Referer. Страница доступа сразу очищает адрес через `history.replaceState`, затем обменивает токен на сессию POST-запросом.
- Cookie `__Host-shootboard`: HttpOnly, Secure, SameSite=Lax, Path=/, без Domain. Secure не отключается даже в разработке; для HTTP-исключения используйте именно localhost в современном браузере. Для общего сервера обязателен HTTPS.
- Права проверяются сервером на каждом запросе, изменение статуса и запись журнала выполняются в одной транзакции. Конфликт одновременных отметок возвращает 409 с обновлением данных.
- CSRF: проверка Origin и токена сессии; CSP, no-store, no-referrer, запрет iframe. Ограничение попыток входа хранится в SQLite.
- Пароль администратора хранится как scrypt-хеш с отдельной солью. Нет универсального пароля или автоматически создаваемого администратора.
- Google refresh/access tokens зашифрованы AES-256-GCM ключом DATA_KEY; доступны только серверу. Настройки Google и журнал доступны только администратору.
- Все участники видят изменения при автоматическом опросе каждые 5 секунд в открытой активной вкладке. Скрытая вкладка обновляется при возврате. Формы во время ввода не перерисовываются.

## Размещение для команды

Локальный адрес доступен только на этом компьютере. Для реальной команды установите приложение на постоянно работающий сервер с доменом и HTTPS. Развёртывание и домен в этой поставке не настроены.

1. Скопируйте папку на сервер и запустите `npm run setup` там. Сохраните `.env` и каталог `data/` на постоянном диске. Ограничьте доступ к ним учётной записью сервиса.
2. Задайте `APP_ORIGIN=https://ваш-домен` без завершающего `/`. Оставьте `HOST=127.0.0.1`, порт 4318. APP_ORIGIN определяет адрес персональных ссылок, Origin-проверку и callback Google.
3. Пример обратного прокси Caddy на том же сервере:

```caddyfile
shootboard.example.com {
    reverse_proxy 127.0.0.1:4318
}
```

4. Запускайте Node как постоянный сервис с автоматическим перезапуском. Используйте один процесс и одну базу. Не запускайте копии с отдельными SQLite-файлами. Для 8–10 человек этого достаточно.
5. Резервное копирование: остановите сервис, скопируйте весь `data/` вместе с `.env`, затем запустите сервис. Не копируйте один SQLite-файл во время записи, игнорируя WAL. Потеря DATA_KEY лишит доступа к сохранённым токенам Google.
6. При переходе с localhost на домен выпустите новые персональные ссылки. Данные на сервере должны быть общими для всех устройств.

Sites здесь не используется как место размещения: приватный вход платформы потребовал бы дополнительного аккаунта у сотрудников. Код готов для обычного HTTPS-хостинга Node.js.

## Google Calendar

Интеграция написана с настоящими OAuth 2.0 и Calendar API, без имитации подключения. Для работы нужны ваши реквизиты Google Cloud; проверка с реальной учётной записью в этой среде не выполнялась.

1. В Google Cloud включите Calendar API и настройте OAuth consent screen. При режиме Testing добавьте аккаунт администратора в test users. Учтите ограничения Google на срок refresh token в тестовом режиме.
2. Создайте OAuth client типа Web application. Authorized redirect URI: `APP_ORIGIN/api/google/callback`, например `https://shootboard.example.com/api/google/callback`.
3. Добавьте `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` в серверный `.env`, перезапустите сервис.
4. Администратор → Настройки → Подключить Google Calendar → выбрать календарь, в том числе общий с правами просмотра.

Запрашиваются только calendar.events.readonly и calendar.calendarlist.readonly. Сервер не отправляет изменения событий в Google. Обмен кода, PKCE и state, обновление токенов, API-запросы выполняются на сервере; callback привязан к сессии администратора.

Синхронизация выполняется каждую минуту, пока сервер работает, и по кнопке «Обновить». Используются calendar ID + event ID, пагинация, incremental sync token, повторная полная загрузка при 410, привязка по calendar ID и event ID. Изменение локальных задач или команды никогда не отправляет их в Google и не удаляет при импорте.

Повторяющиеся события импортируются как отдельные экземпляры. Название, даты, место и описание импортированного события в ShootBoard изменить нельзя; меняйте их в Google Calendar, если у вас есть соответствующие права. Команду и задачи администратор редактирует в ShootBoard. Отменённые события сохраняются с задачами и пометкой. Можно сменить выбранный календарь: события прежнего календаря скрываются, его задачи и назначения сохраняются. При возврате они снова видны. Формы показывают время устройства, сервер хранит время с часовым поясом. События на весь день сохраняются как календарные даты без сдвига часового пояса. Конечная дата Google не включается в событие. В месяце многодневные события занимают все дни полосами с продолжением между неделями и месяцами. В списке и карточке виден полный период. Создание локальных событий на весь день пока не предусмотрено.

Полноценный прогон OAuth, отмен и повторений с реальным Google Calendar нужно выполнить после подключения вашего аккаунта. Тесты с подменённым API не заменяют эту проверку.

## Состав

- `server.mjs` — авторизация, права, SQLite, журнал, Google OAuth и импорт только для чтения.
- `public/` — интерфейс администратора и сотрудника.
- `setup.mjs`, `.env.example` — первоначальная настройка.
- `test/` — проверки безопасности, хранения и синхронизации.

Нет профилей, email-приглашений, дополнительных ролей доступа и внешних библиотек. Роль на конкретной съёмке — обычное текстовое поле.


## Обновление до версии с общими календарями

Остановите приложение (Ctrl+C). Замените server.mjs и public/ файлами новой версии. Сохраните свои .env и data/; не запускайте setup заново. Затем запустите start.cmd. В письме Google примите приглашение к общему календарю тем же аккаунтом, который подключён в ShootBoard. В настройках выберите общий календарь. Если ранее выдавали право записи, отзовите доступ Shoot в настройках безопасности Google-аккаунта и подключите Google повторно: новая версия запрашивает только чтение. Сервер новой версии запрещает запись в Google даже при старом токене.


## Обновление многодневного календаря

Остановите приложение (Ctrl+C). Сохраните копию своей рабочей папки. Замените только server.mjs и всю папку public/ из этой версии. Оставьте свои .env и data/ на месте, setup повторно не запускайте. Запустите start.cmd, нажмите Ctrl+F5 в браузере. Затем Настройки → Google Calendar → Обновить.

Схема базы обновляется автоматически добавлением признака события на весь день. Первый импорт после обновления заново читает даты Google, сохраняя существующие ID мероприятий, сотрудников, назначения и задачи. Переподключать Google не требуется. На телефоне календарь прокручивается горизонтально. Проверено 12 автоматических тестов, включая обновление прежней базы и сохранение задач; календарь проверен на тестовых данных в браузере.


## Единый календарь

Разделение на предстоящие и прошедшие убрано. По умолчанию открывается месяц; все мероприятия доступны через стрелки выбора месяца. В режиме «Список» отображаются все даты. Счётчик показывает общее число съёмок. Для обновления с графитной версии достаточно заменить всю папку public/ и нажать Ctrl+F5 в браузере. Свои .env и data/ сохраните.


## Выбор периода мероприятий

На расписании доступны «Предстоящие», «Прошедшие», «Последние 3 месяца», «Последние 6 месяцев», «Смотреть все». По умолчанию выбраны предстоящие, включая уже начавшиеся, но ещё не завершённые съёмки. Последние 3/6 месяцев — завершённые мероприятия за скользящий период от текущей даты назад; учитывается дата окончания. Прошедшие отображаются от новых к старым. Все фильтры работают в списке и месяце. Если в показанном месяце нет событий выбранного периода, календарь переходит к ближайшему подходящему событию. «Смотреть все» снимает ограничения по периоду.

Для обновления с предыдущей версии замените только всю папку public/ и нажмите Ctrl+F5. Свои .env и data/ сохраните.


## Верхний блок информации

Над расписанием остаётся только карточка «Задачи в работе». Нажатие открывает раздел невыполненных задач и сбрасывает ранее выбранные фильтры мероприятия и ответственного. Администратор видит задачи команды, сотрудник — свои. Счётчики съёмок и сотрудников убраны. Для обновления замените всю папку public/ и нажмите Ctrl+F5; свои .env и data/ сохраните.

## Новый главный экран: карточки

По умолчанию открываются карточки и фильтр «Актуальные»: идущие сейчас и предстоящие съёмки. «Предстоящие» показывает только ещё не начавшиеся. «Смотреть все» выводит сначала текущие события, затем будущие по близости начала, затем завершённые от недавних к старым; отменённые идут последними. История доступна также через прежние фильтры 3/6 месяцев.

На странице четыре мероприятия: четыре колонки на широком экране, две на планшете и одна на телефоне. Стрелки перелистывания показывают номер страницы и диапазон мероприятий. При смене фильтра открывается первая страница; обновление данных сохраняет текущий номер страницы, если она существует, и открытую карточку. Завершённые мероприятия сохраняют невыполненные задачи и предупреждение об остатке. Пересечения обозначаются цветом и текстом.

Установка обновления: остановите приложение через Ctrl+C. Сохраните резервную копию рабочей папки. Замените server.mjs и всю папку public/ из этого архива. Сохраните собственные .env и data/ без изменений. Запустите start.cmd и нажмите Ctrl+F5. Переподключение Google не требуется. Сервер изменён только для выдачи нового файла интерфейса cards.js.

Все 22 автоматических теста прошли. В браузере проверены загрузка карточек и перелистывание. В текущем окне браузера была доступна ширина планшета; отдельная проверка широкого и мобильного размеров в браузере не завершена. Адаптивные сетки заданы в CSS.
